# ML: обучение и прогнозы

Здесь только признаки, обучение, inference, объяснения и временная проверка. HTTP-маршруты находятся в `backend/api/`, CSV-подготовка — в `backend/data_pipeline/`, файлы моделей — в `models/`.

| Файл | Ответственность |
|---|---|
| `feature_engineering.py` | Общий allowlist признаков обучения и прогноза |
| `train_waiting_model.py` | Временное разделение, удаление поздних обучающих исходов, обучение |
| `waiting_estimator.py` | Групповые медианы из обучения + CatBoost для редкой истории |
| `predict.py` | Загрузка актуальных артефактов, одиночные и пакетные оценки |
| `load_forecast.py` | Семь прямых прогнозов потока из одной даты отсечения |
| `explanations.py` | SHAP для CatBoost; основание и число случаев для медиан |
| `validation.py` | Расширяющиеся окна, ошибки по группам и горизонтам |
| `notebooks/` | Исследовательские агрегаты, не рабочий сервер |

Из корня проекта:

```bash
python -m scripts.bootstrap
python -m ml.train_waiting_model
python -m ml.load_forecast
python -m ml.validation
```

Обучение сохраняет результаты в `models/`. Для ожидания v3 CBM нужен вместе с `model_metadata.json`, содержащим калибровочные агрегаты; один CBM не воспроизводит итоговую оценку.

Рефакторинг меняет расположение кода, а не алгоритмы, признаки, даты разделения или артефакты. Старые данные и обученные модели не перемещаются и не требуют переобучения только из-за новой структуры.

[Результаты и ограничения](../docs/VALIDATION_RESULTS.md). Незавершённые направления не имеют известного срока; короткая история и цензурирование ограничивают качество.
