# Бэкенд

- `main.py`: создание FastAPI, подключение роутеров и middleware.
- `modules/auth/`: вход, сессии, права доступа, PostgreSQL и миграции.
- `modules/accounts/`: список аккаунтов, блокировка и удаление.
- `modules/analytics/`: обзор, справочники, сравнение и SQL-запросы к аналитике.
- `modules/hospitals/`: поиск стационаров и карточка больницы.
- `modules/predictions/`: получение прогноза потока и оценки ожидания из `ml/`.
- `modules/briefings/`: просмотр сводки, подтверждение и генерация PDF.
- `modules/system/`: состояние сервиса, моделей и методология.
- `http/`: общие HTTP-проверки, сериализация, middleware и раздача фронтенда.
- `data_pipeline/`: обнаружение CSV, очистка, связывание, агрегаты и Parquet.
- `core/`: общие настройки, безопасный SQL и атомарный JSON.

Из корня: `python -m scripts.serve` или `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`.

API не обучает модели и не запускает подготовку в ответ на веб-запросы. Он использует готовые файлы из `data/processed/` и функции `ml/`. Пациентские строки и идентификаторы в браузер не отправляются.

Внутри раздела `router.py` принимает запрос и проверяет разрешение, `schemas.py` описывает входные данные, `service.py` собирает результат. Хранение аккаунтов и сессий находится в `modules/auth/store.py`, управление аккаунтами — в `modules/accounts/repository.py`, SQL аналитики — в `modules/analytics/dashboard_data.py` и `modules/analytics/repository.py`. Общие проверки доступа лежат в `modules/auth/dependencies.py`, общие фильтры — в `modules/analytics/dependencies.py`.

Основная функция показывает последовательность действий. Проверки, чтение данных и отдельные расчёты вынесены в именованные помощники внутри того же модуля. Неподходящие условия завершаются ранним возвратом или явной ошибкой; SQL-запросы остаются цельными.

Сервисы проверяют доступ к выбранной больнице до чтения аналитики. Проверка готовности файлов вынесена в `http/data.py`, преобразование агрегатов для JSON — в `http/serialization.py`. PostgreSQL, DuckDB и ML вызываются из синхронных обработчиков, чтобы не блокировать цикл событий.

URL, параметры, cookies и форматы ответов сохранены. Точка входа остаётся `backend.main:app`; `create_app()` позволяет собирать отдельное приложение для тестов.

Зависимости HTTP/SQL-слоя: `backend/requirements.txt`. Полный веб-runtime: `requirements-api.txt` в корне. Настройки памяти и путей: `backend/core/config.py`.
