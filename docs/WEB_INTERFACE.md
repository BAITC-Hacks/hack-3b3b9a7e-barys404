# Веб-интерфейс MedFlow AI

## Что открывать

После сборки фронтенда и запуска API откройте **http://127.0.0.1:8000**. Один процесс обслуживает интерфейс и API. При разработке Vite доступен на **http://127.0.0.1:5173** и передаёт запросы `/api` локальному серверу на порту 8000. Спецификация API находится по адресу **http://127.0.0.1:8000/docs**.

## Основной сценарий

Сначала открывается публичная страница `/#welcome`. Войдите через `/#login` выданной учётной записью. Кабинет и организация определяются сервером. [Настройка и тестовые аккаунты](AUTH_SETUP.md).

1. На **Обзоре** видны направления, число стационаров, наблюдаемое ожидание, госпитализации и недельная динамика. Нажмите на стационар в списке справа.
2. В **Карточке стационара** видны его показатели и наиболее частые профили. Отсюда можно перейти к сравнению или прогнозу.
3. В **Прогнозах** откройте «Поток направлений»: там семь дней после последней даты в выгрузке и средняя ошибка модели. На вкладке «Время ожидания» уже подставлен наблюдавшийся профиль; нажмите «Рассчитать ожидание» для оценки и факторов модели.
4. В **Как читать показатели** посмотрите определения, ограничения и общую ошибку моделей. Техническое состояние доступно администратору через защищённый API.
5. Внизу **Карточки стационара** и **Сравнения** расположен блок **Сводка для обсуждения**: выберите вопрос, подготовьте просмотр, проверьте цифры и ограничения, отметьте подтверждение и скачайте PDF. До подтверждения кнопка заблокирована. PDF содержит агрегаты 1–3 стационаров, версии и периоды проверки моделей, вопрос специалисту и ограничения; данные пациентов отсутствуют.

При смене периода, профиля, региона, выбранных больниц или вопроса просмотр PDF и отметка сбрасываются. API повторно вычисляет агрегаты и сверяет контрольную сумму контекста, пользователя, данных и метрик; изменение версии между просмотром и скачиванием даёт `409` с предложением повторить просмотр. Подтверждение означает локальный просмотр аналитиком, а не электронную подпись или разрешение автоматически перераспределять пациентов.

Раздел **Стационары** показывает все организации с направлениями в выбранной выборке, по 50 на страницу. Поиск охватывает весь список, включая следующие страницы. Если выбран профиль, число организаций закономерно уменьшается; активный профиль показан над таблицей. Для показателей ожидания и доли отказов малые группы остаются без оценки (прочерк), а не превращаются в ноль. При новом входе фильтры и данные предыдущего аккаунта очищаются.

**Авторизация и RBAC:** госорган видит все больницы, каталог и сравнение; сотрудник — только свою организацию и её прогнозы. Вместо переключателя показаны имя, роль и выход. Прямой URL или HTTP-запрос не расширяют права. Для показа другой роли выйдите и войдите другим тестовым аккаунтом.

## Откуда приходят данные

React обращается только к `/api`. API использует `backend/analytics/dashboard_data.py` для агрегатов DuckDB, `ml/predict.py` и `ml/explanations.py` для ожидания, `ml/load_forecast.py` для семидневного прогноза. Постатейные записи направлений и составные ключи пациентов в браузер не отправляются. Веб-запросы не переобучают модели и не запускают тяжёлую подготовку CSV.

Основные маршруты:

| Маршрут | Содержимое |
|---|---|
| `/api/bootstrap` | Доступный период и значения фильтров |
| `/api/overview` | Агрегированные показатели, недельная динамика, изменения за два семидневных окна |
| `/api/hospitals` | Все стационары с поиском по всей выборке, `limit`/`offset` и агрегатами |
| `/api/hospital/overview` | Карточка выбранного стационара |
| `/api/hospital/forecast` | Наблюдаемая история и прогноз на семь дней |
| `/api/compare` | Сопоставление организаций за общий период |
| `/api/wait-options`, `/api/predictions/wait` | Параметры и расчёт ожидания |
| `/api/models` | Техническая готовность и ошибки; только администратор |
| `/api/methodology` | Общие метрики качества |
| `POST /api/briefings/preview` | Сводка, вычисленная сервером, и контрольная сумма контекста |
| `POST /api/briefings/pdf` | PDF после подтверждения актуального просмотра; CSRF обязателен |
| `/api/auth/*` | Вход, сессия, выход, CSRF, смена пароля |

## Обновление данных

Положите новую выгрузку CSV в `data/raw/`, затем из корня проекта запустите:

```bash
.venv/bin/python -m scripts.bootstrap
```

Если файлы или подготовленные данные изменились, API помечает модели устаревшими и блокирует соответствующие прогнозы до пересборки. После подготовки выполните `python -m scripts.auth sync-organizations` и перезапустите API, чтобы обновились списки фильтров и готовая страница получила актуальный контекст. Исходные CSV, Parquet и CBM остаются вне Git.

PDF требует ReportLab и шрифты Matplotlib; зависимости включены в `requirements-api.txt` через `backend/requirements.txt`.

## Как читать результаты

Текущая история регистрации: **1 января — 31 марта 2025 года**. Прогноз потока относится к **1–7 апреля 2025 года**, а не к календарной неделе запуска приложения. Поток направлений не равен занятости коек. Ожидание обучено на завершённых госпитализациях и не указывает индивидуальную дату госпитализации. Регионы в фильтре — **регионы происхождения направлений**, не расположение больницы. Сравнение организаций не учитывает сложность случаев и мощность коек.

Ожидание v3: медиана обучающей истории стационара и профиля при ≥10 случаях, затем медиана стационара. Для редкой истории — CatBoost; для отрицательного ответа или нового стационара — явно обозначенная оценка профиля/общей истории. Все агрегаты рассчитаны только по исходам до 14 марта, без включения тестовых случаев. Общий MAE на регистрации 14–31 марта — 5,2709 дня (прежний CatBoost: 6,5133).

Для групповой оценки форма оставляет только профиль и показывает основание, число случаев и дату отсечения. Для CatBoost доступны параметры направления и SHAP. При достаточном числе тестовых случаев показана ошибка конкретной пары «стационар × профиль», которая может сильно отличаться от общей. Это оценка полного наблюдённого ожидания, не оставшегося срока в сегодняшней очереди. Нулевая обучающая медиана допустима; значения меньше 0,1 дня показаны как «<0,1», без обещания немедленной госпитализации.
