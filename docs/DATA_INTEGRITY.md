# Достоверность отображаемых данных

Правила первого этапа, 26 сентября 2026. Применяются к React/FastAPI; общие SQL-агрегаты используются и прежним Streamlit.

## Исходы направлений

Общее число направлений включает пять исходов: госпитализация, отказ, отсутствие записанного исхода, некорректный исход, конфликтующие исходы. Последние два показаны общей строкой с расшифровкой количества. Их нельзя включать в оценку ожидания. Отсутствие исхода не означает сегодняшнюю активную очередь.

Для текущей выгрузки: 761 434 направления = 570 066 госпитализаций + 83 437 отказов + 3 954 без исхода + 103 976 некорректных + 1 конфликтующий исход. Госпитализации с известным исходом и допустимые случаи для оценки ожидания — разные знаменатели; допустимых случаев 554 416.

## Малые выборки

`MIN_METRIC_GROUP_SIZE = 10` в `backend/core/config.py` задаёт нижнюю границу для описательных статистик. Среднее, медиана и P90 ожидания не возвращаются, если в выбранной группе меньше десяти допустимых завершённых случаев. Число всех направлений не заменяет число допустимых исходов. Доля отказов требует десяти известных исходов, её знаменатель — госпитализации плюс отказы. Страница сравнения может применять более строгий выбранный пользователем порог.

При недостатке наблюдений API возвращает `null`, интерфейс показывает прочерк с объяснением. Настоящий ноль остаётся нулём. Числа направлений и категории исходов сохраняются для согласования итогов; эта политика статистик сама по себе не является гарантией полной защиты от восстановления информации по множеству пересекающихся запросов. В прежней гистограмме ожидания малые дневные группы также скрыты.

## Недельная динамика

Неделя — понедельник–воскресенье. API возвращает начало недели, фактические границы выбранного интервала, число входящих в него дней и признак `partial_week`. Границы учитывают область доступа пользователя и выбранные фильтры. Недельный график отображает полные интервалы; неполные показаны отдельно с количеством дней и направлений.

Например, 31 марта 2025 — один день, а не полная неделя. Его 15 183 направления не соединяются на графике с 41 653 направлениями за 24–30 марта. Первая неделя также неполная: в истории доступны 1–5 января.

Пустые внутренние календарные недели сохраняют своё место и нулевой счётчик. Это отсутствие записей в файлах, а не подтверждение полноты поставки источника или отсутствия пациентов. Признак полного интервала не доказывает, что все события были переданы источником.

## Качество моделей

`/api/methodology` отдаёт для каждой модели статус, строковую версию, даты теста и MAE/RMSE/baseline MAE. Метрики возвращаются только для актуальных артефактов с корректной оценкой качества. При отсутствии, устаревании или повреждении артефактов поле `metrics` равно `null`. Недоступность одной модели не скрывает другую. Обучающие медианы, размеры больничных групп и перечень источников через этот общий маршрут не публикуются.

Версия и период проверки также показаны рядом с результатами прогнозов. Общие ошибки относятся ко всему тесту; их нельзя выдавать за ошибку выбранной больницы. Ошибка пары «больница × профиль» обозначается отдельно при достаточном числе тестовых наблюдений.

После обновления локальных артефактов:

| Оценка | MAE | Baseline MAE | Регистрация теста |
|---|---:|---:|---|
| Ожидание v3, дни | 5,2709 | 7,1198 | 14–31 марта 2025 |
| Поток v2, направления / организацию в день | 3,6027 | 5,2655 | 25–31 марта 2025 |

Ожидание v3 преимущественно использует обучающие медианы больницы/профиля. CatBoost остаётся для редкой истории. Это не новый эксперимент со смесью моделей. Временная проверка пересчитана на трёх окнах; её протокол и ограничения описаны в [результатах валидации](VALIDATION_RESULTS.md). Ранние окна пересекаются с историей выбора метода ожидания и не являются независимым подтверждением его превосходства.

## Воспроизведение

```powershell
.\.venv\Scripts\python.exe -m scripts.bootstrap --validate
.\.venv\Scripts\python.exe -m scripts.demo_check
.\.venv\Scripts\python.exe -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
```

Для полного pytest требуется тестовая PostgreSQL согласно [инструкции авторизации](AUTH_SETUP.md). Фронтенд-тесты проверяют реальную серверную разметку React: категории исходов, исключение неполной недели из графика и скрытие устаревших метрик. Это не визуальные или браузерные сквозные тесты. Модели, данные и резервные копии сохраняются локально и не включаются в Git.
