# Автодеплой MedFlow

Пуш в `main` репозитория `BAITC-Hacks/hack-3b3b9a7e-barys404` запускает
workflow **Deploy MedFlow**. Его можно запустить вручную во вкладке Actions.

Фронтенд собирается на GitHub, не на общем VPS. На сервер передаются только код и
готовый `frontend/dist`. Исходные CSV, Parquet, модели, `.env`, PostgreSQL и
аккаунты не входят в архив и не заменяются.

## Что происходит при обновлении

1. `npm ci` и `npm run build` собирают фронтенд.
2. Архив доставляется через отдельный SSH-ключ с проверкой ключа сервера.
3. Код распаковывается в новую папку версии.
4. Используется существующее Python-окружение. Если изменились runtime
   requirements, создаётся отдельное окружение; рабочее не обновляется на месте.
5. До переключения проверяются импорт API, совместимость данных и доступность
   обеих моделей. Обучение моделей и изменение схемы БД автоматически не запускаются.
6. Ссылка `medflow-current` переключается на новую версию, приложение перезапускается.
7. Проверяются API health и соответствие главной страницы новой сборке.

Сборка и предварительные проверки не останавливают работающий сайт. При переключении
есть короткий перерыв на перезапуск. Если приложение не запускается, receiver
возвращает предыдущую версию и перезапускает её.

Автоматический откат применяется при ошибке запуска и локальной проверки сайта.
Ошибка внешнего HTTPS-прокси отмечается в Actions, но не откатывает уже здоровый
процесс приложения. Проверка health не заменяет тесты всей бизнес-логики.

Деплои выполняются по одному, без отмены уже начавшегося переключения. Старый
workflow Tests не изменён: он может отдельно запускаться при пушах, но не блокирует
этот workflow. Сообщения коммита с `[skip ci]` пропускают автоматический запуск;
в таком случае нужен ручной запуск Deploy MedFlow.

## Сервер

```text
/home/barys404/apps/
  medflow-5ae817c/         исходный деплой, общие данные, модели, .env и старое окружение
  medflow-current -> ...  текущая версия приложения
  medflow-deploy/
    receiver.py          доверенный обработчик SSH-деплоя
    releases/            отдельные версии кода и фронта
    environments/        окружения по fingerprint runtime requirements
    incoming/            временные архивы
    failed/              сохранённые незавершённые версии и окружения
    state.json           текущая и предыдущая версия
```

Не удаляйте `medflow-5ae817c`: новые версии используют его данные, модели, `.env`
и исходное окружение. Окружение не перемещается после создания.

Существующая служба `medflow-postgres.service` не меняется. Служба приложения
`medflow.service` запускается из `medflow-current`.

Receiver устанавливается отдельно от присылаемого кода. Изменение
`scripts/deploy/receiver.py` в Git не обновляет доверенный обработчик на сервере:
для этого нужна отдельная установка через обычный SSH.

## Секреты GitHub Actions

- `MEDFLOW_DEPLOY_KEY` — отдельный приватный SSH-ключ деплоя.
- `MEDFLOW_DEPLOY_KNOWN_HOSTS` — заранее проверенный публичный ключ VPS.

Приватный ключ не находится в Git, `.env` или workflow. Его публичная часть в
`authorized_keys` разрешает только команду загрузки версии. Интерактивный shell,
PTY, перенаправление портов и агента запрещены. У GitHub Actions нет SSH-пароля.
Ключ деплоя нужно считать доступом к коду работающего приложения: изменения в
`main` должны поступать только от доверенных участников команды.

## Управление

В SSH от пользователя `barys404`:

```bash
systemctl --user status medflow.service --no-pager
journalctl --user -u medflow.service -n 50 --no-pager
readlink -f /home/barys404/apps/medflow-current
```

Откат на предыдущую работающую версию:

```bash
/home/barys404/.local/bin/python3.12 /home/barys404/apps/medflow-deploy/receiver.py --rollback
```

Это откат кода и фронта, не данных, аккаунтов или схемы PostgreSQL. Изменения,
требующие миграций БД или переобучения моделей, нужно готовить отдельно.

Старые версии и окружения автоматически не удаляются. Следите за свободным
диском. При изменении зависимостей требуется минимум 2,5 ГБ свободного места;
если места не хватает, текущий сайт не переключается на новую версию.
